# @aqlamna/linter — Arabic Quality Linter

Lints `.qalam` prose for Arabic writing-quality issues defined in
`ARABIC_MASTERY.md`. Zero runtime dependencies — uses only `@aqlamna/core` for
tokenisation.

## What it does

- Reads **TEXT tokens only** from the `.qalam` tokeniser — never inspects
  passage headers, variable names, keywords, diverts, tags, or comments.
- Matches **pair rules** (every ❌/✅ table row in ARABIC_MASTERY.md) with
  Arabic word-boundary checks — `"ورد"` does not match inside `"الوردة"`.
- Matches **pattern rules** (`rules-extra.json`) with regex — hand-written
  rules that tables cannot express (guillemets, قام بـ, تمّ, مشاكل, مدراء).
- **Advisory rules** (§§1.1–1.7, §5) are included for reference but never
  produce diagnostics — they describe narrative craft, not surface text.

## Severity levels

| Severity | Meaning | Editor rendering |
|----------|---------|-----------------|
| `warning` | Likely issue — consider changing | Amber wavy underline |
| `info` | Judgement call — suggestion only (§1b.5 verb precision) | Grey dotted underline, no gutter marker |
| `error` | Not used by this linter (reserved for compiler errors) | — |

## Important: pair rules over-match

**Pair rules are extracted from tables, and a table row is an example — not a
regex.** A pair rule catches every occurrence of the bad text, even in contexts
where the correction does not apply. For example:

- `يرفع` → `يُزيح` is correct when the meaning is "move aside," but "رفع عينيه"
  (raised his eyes) is standard Arabic. The linter flags both.

**The linter suggests and never blocks.** It does not auto-correct. It is a
writing aid, not a gate.

When you add a new ❌/✅ row to ARABIC_MASTERY.md, run `npm run build:rules` to
regenerate, then check the real-world story diagnostics. If a rule over-matches,
consider narrowing the bad text in the table, or accept that some false
positives are inherent to pair matching.

## Editor integration

- Toggle in Settings panel (persisted to localStorage as `aqlamna-quality-lint`)
- Hover shows the rule message and § reference
- One-click fix for `warning`-level rules with suggestions
- Rules meta display: active rule count + ARABIC_MASTERY.md last-modified date

## Scripts

```
npm run build:rules   # Regenerate src/generated/rules.ts from ARABIC_MASTERY.md
npm test              # Run 142 generated tests (126 pair + 3 dedup + 5 pattern + 8 advisory)
npm run build         # Compile TypeScript
```

## Deduplication

When a pair rule and a pattern rule fire at the same (line, column, length),
the pattern rule is kept and the pair rule is dropped. This prevents duplicate
diagnostics for overlapping rules like مشاكل (pair `2.2.2` + pattern
`2.2-mashakil`) and مدراء (pair `2.2.1` + pattern `2.2-mudara`).

## Rule loading

Rules are loaded from `src/generated/rules.ts` — a TypeScript module emitted by
`scripts/build-rules.mjs`. This avoids JSON import-assertion compatibility
issues between Node and browser environments.
